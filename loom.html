Case study

loom

The component pattern this site is modeled on.

The pattern

loom is built as single-file-per-class ES modules around an abstract base component with a template-method lifecycle: mount() runs render(), then bind(). Subclasses fill in the hooks; the base class refuses direct instantiation. State stays in private fields, types live in JSDoc, and larger structures follow the Block/Sequence pattern.

Content stays in plain semantic HTML — the component layer attaches behavior, it never generates page markup. With JavaScript off, the page still reads complete.

Why it matters

No frameworks, no build step, no bundler. Every line earns its place: the code stays readable by a human, and the deploy stays rsync-simple. This very site borrows the same pattern for its own component layer.
